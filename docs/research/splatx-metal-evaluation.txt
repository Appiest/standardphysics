SplatX Metal: measured local evaluation, 2026-09-20

VERDICT
Native Metal training works and is fast on this Mac. The tested Moffett pilot
is NOT suitable for release: recognizable training views do not generalize to
the eight withheld validation views. Keep SplatX as an experimental training
backend, not a demonstrated replacement for Brush. No production scene changed.
This is a 32-view center-room pilot, not a full-floor or phone benchmark.

VISUAL RESULT AND METRICS
Inspected the training preview and validation views 144, 149 and 177. The training
preview reproduces furniture/colors but blurs distant detail and contains people.
Withheld views show severe holes, stretched splats and disconnected surfaces.
This fails the requested navigable, detailed room quality. A better schedule or
more training coverage might help; this trial does not isolate the cause or
establish the backend's quality ceiling.

Metrics reuse packages/pipeline/standardphysics_pipeline/render_efficiency/metrics.py:
decoded sRGB float64 [0,1], static mask L>250, mean of per-view PSNR, SSIM with
11x11 Gaussian window sigma 1.5 and windows wholly inside the static mask.
Validation cameras were rendered with SplatX's own native renderer at 1280x960.
An exported-Ply round-trip of training camera 0 agrees with the in-memory preview:
maximum channel difference 1/255; mean absolute difference 0.000002713/255.
Thus the obvious validation failure is not explained by a gross export-render
coordinate flip. SH2 PLY is padded with zero SH3 coefficients for compatibility.

BRUSH COMPARISON: IMPORTANT SPLIT ERROR
Both PLYs can be rendered in the same native renderer. But the existing Brush
b0-v2-r1 used --eval-split-every 5, which does not honor the named manifest split.
Its actual saved evaluation views at step 5000 are:
038,083,088,186,210,226,241,296.
The intended validation views are:
144,149,166,177,182,186,190,195.
Only 186 overlaps. Seven intended validation views are outside Brush's actual
evaluation set, so this is not a common-heldout comparison. Its diagnostic
21.9253 dB / 0.69126 SSIM on these images must NOT be used to rank backend quality.
Iterations, splat counts, SH degrees, training masks and RNG seeds also differ.
The existing Brush process took 261.74 s, but calling SplatX "4x faster" from
these unequal workloads would be misleading. The split issue was sent to the
existing render-score reviewer; no other agent's data or code was changed.

WHAT IT PROVIDES / WHAT IT DOES NOT
- Native C++/Swift/Metal differentiable Gaussian training, MCMC, SH0-3,
  checkpoint/resume, PLY/SPZ export and native rendering: implemented.
- Per-image calibrated cameras and LiDAR point initialization: supported through
  COLMAP. We successfully tested the adapter and training with existing poses.
- Person-exclusion loss masks: absent. Image alpha is composited onto black;
  blacking out people is not equivalent to excluding their loss.
- LiDAR depth or normal loss, geometry anchoring: absent from trainer input/loss.
  Depth-gradient buffers are zero. RGB optimization can move the seed geometry.
- Lens distortion in CLI: only PINHOLE/SIMPLE_PINHOLE. The GUI has a separate
  rectification importer; CLI callers must supply appropriately calibrated inputs.
- Rendered coverage alpha: not exposed correctly for coverage scoring through
  current RGB PNG/opaque-RGBA exports. PLY Gaussian opacity does exist.
- Semantic recognition, outlet identification, reachability, collision surfaces,
  floor alignment, measured geometry and ADA reasoning: separate application work.
- iPhone training, mobile memory/thermals and our actual web viewer integration:
  not tested here. Native Metal performance does not establish browser performance.
- Code licenses inspected: Apache-2.0 project/metal-cpp/swift-argument-parser;
  MIT SPZ and MetalSplatter. No noncommercial clause found in those dependencies;
  preserve licenses/notices. This is a source inspection, not a legal opinion.

NEXT DECISION
Use the existing native trainer rather than writing new Metal rasterization or
backpropagation kernels. Before considering production promotion:
1. Fix the benchmark adapters so each trainer receives identical explicit
   training IDs; evaluate the same withheld IDs. Never infer parity from counts.
2. Use matched budgets/resolution/SH/seeds where supported, record actual splats,
   repeat measurements, and inspect views beyond captured training viewpoints.
3. Add and test person-mask loss support before using dynamic Moffett images.
4. Evaluate visibility-filtered LiDAR seeds and robust depth/surface constraints;
   keep the measured collision/accessibility model independent of splat positions.
5. Test the exported assets in the actual web viewer and on a physical iPhone.
Do not promise an overnight production conversion from this experiment alone.
