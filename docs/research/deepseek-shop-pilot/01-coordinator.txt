STANDARD PHYSICS PARALLEL BUILD CONTRACT — version 1, 2026-09-21

OUTCOME AND SCOPE
Build one connected journey first, with an assisted mode usable in a new shop:
capture, upload complete evidence, find/review objects, select customer route and
counter, screen selected requirements, propose safe furniture changes, recheck,
export. Automatic detections and manually marked items must remain distinguishable.
Implement all four target object workflows: outlet, television, service counter,
restroom entrance. A missing class in Moffett must stay missing/unknown; use a
clearly separate fixture to test its UI, not a fabricated Moffett object.

The longer product includes restroom fixtures, broader reach/door/counter rules,
general multi-room registration, trustworthy photo meshes and multi-shop accuracy.
They remain assigned in the same lanes' Phase B work, not abandoned after the pilot.
The midnight gate is an installable and honestly limited assisted pilot, not a
promise that every long-term gate or legal requirement can be met overnight.

SEPARATE DELIVERABLES, NOT ONE COMPLETION PERCENTAGE
Use the certificate definitions in 04-hard-gates.json:
- software_verified: code/integration/evidence consistency works.
- saved_capture_verified: real Moffett evidence traverses the production flow.
- phone_pilot_ready: installed physical-phone capture-to-review works tonight.
- shop_field_validated: the actual new boba-shop journey works on site later.
- automatic_semantics_benchmark_passed: independently labeled held-out targets meet
  metrics on that benchmark; this does not establish general product accuracy.
- scoped_assessment_evidence_ready: all requested checks have traceable outcomes;
  unknowns and violations may exist and remain visible.
- scoped_requirements_satisfied: a separate per-requirement conclusion, only where
  applicability, reviewed logic, sufficient measurement and all conditions support it.
- photo_mesh_500_verified: independent rendering acceptance, not a pilot substitute.
No automated "whole shop ADA compliant" certificate is provided. Store a real
qualified review as an attributed external document only if one is actually given.
Neither a reviewer title nor a software gate is a government/legal certification.

LAUNCH SCHEDULE / CRITICAL PATH
Wave 0: coordinator contracts + Q independent baseline/receipt verifier + C capture
inspection/build preparation + S source inventory/detection baseline. Only the
coordinator writes shared schemas. Other lanes can prepare tests against existing
types while contracts are frozen; do not invent incompatible placeholder payloads.
Four-slot example: slot 1 K, slot 2 Q, slot 3 C, slot 4 S. Once Q checkpoints the
baseline and initial evaluator, replace slot 2 with B. Once C checkpoints a tested
build or is waiting on the phone, replace slot 3 with G. Once S hands production
integration to B, replace slot 4 with U. Later replace completed lanes with A/R/E/V
according to dependencies; reactivate Q at every integrated milestone. Waiting
sessions remain checkpointed, not falsely counted as actively accomplishing tasks.
K records session IDs and replacement conditions; never launch all named cards
at once and hope the machine or agent service schedules them correctly.
Wave 1: B backend lifecycle + C iOS + S semantics + G geometry, as slots permit.
Q reclaims a slot for early contract and adversarial reviews. Feed U UI immediately
after the minimal contract is frozen; swap completed workers rather than idle them.
Wave 2: A assessment + U UI + R redesign + E export/deployment; B integrates actual
discovery outputs as soon as S hands them off. G reviews measurement boundaries.
Wave 3: Q runs full-path/physical-device acceptance while owners repair failures.
V photo mesh runs independently whenever one heavy-job slot is available. Its
failure never blocks evidence/map development; its success never satisfies that.
Phase B: after the pilot handoff keep A/R/S/G/V working on their remaining gates
and broader requirements. Reuse sessions and existing contracts; don't restart.

Dependencies describe HANDOFFS, not a ban on preparing independent tests early.
G00's full adversarial certification happens after relevant components exist;
freeze its policy early, but don't wait for all mutation tests to pass before coding.
Do not delay all integration until every lane is finished. Thin vertical slices:
I0 contract roundtrip; I1 upload->evidence closure->worker->graph; I2 graph->crop
review->saved correction; I3 role/route->assessment->proposal->recheck->export;
I4 fresh phone scan through I1-I3. Q exercises each on the integration branch.

tests/commands; real versus synthetic evidence; outstanding issues; next consumer.

REPAIR LOOP — REQUIRED AT EVERY LEVEL
For each failing gate:
  1. Save actual failure, frozen input/revision, expected invariant, owner and metric.
  2. Write one falsifiable hypothesis BEFORE editing or running an expensive job.
  3. Make the smallest responsible-layer change; preserve required behavior.
  4. Run targeted regression proof, then changed contract consumers/integration.
  5. Q recomputes the gate from raw artifacts. A source change invalidates dependent
     results, not unrelated evidence. Bind dirty-source hashes as well as commits.
  6. Atomically checkpoint status, artifact hashes, elapsed time and next action.
Repeat while actionable. Three failed repairs for one hypothesis trigger a
different hypothesis/reviewer, not a fourth cosmetic edit. Two hypotheses without
measurable progress trigger coordinator architecture review/reassignment. This is
NOT permission to declare done: pursue other actionable lanes and collect missing
evidence. Stop that experiment as no_progress if its input is inadequate; name
the exact recapture/control measurement needed. Resume when new evidence arrives.
Transient network errors: at most three tries with jittered backoff (about 2/5/15s);
authentication/schema/permission errors: no blind retry, surface the exact error.
No automatic relaxed threshold, test deletion, benchmark shrinking or favorable
midpoint substitution. Any justified policy correction needs independent review,
new version and BOTH old/new results; cannot retrospectively pass an old claim.

WHAT COUNTS AS PROGRESS
An integrated invariant now passes with reproducible evidence; a previously
unknown cause is localized; a necessary physical input is collected; a measured
failing metric improves on the fixed evaluation set. More code, more tests,
longer reports and edited status flags alone are not progress. Whole assessment
outcomes are NOT optimized toward fewer reported violations or fewer unknowns.

CHECKPOINTS AND RESUME
Create runs/shop-pilot/<actual-run-id>/ (never overwrite past runs). Coordinator
alone writes progress.json every completed subtask and at least every 10 minutes.
Each lane writes its own lane-<id>.json and immutable receipt files. Suggested
fields: schema_version, run_id, deadline, head, dirty_source_digest,
contract_hash, policy_hash, lanes[{owner,session,worktree,files,state,next_action}],
gates[{id,status,receipt_paths,blocker,next_action}], certificates, asked_inputs,
artifact_index, latest_checkpoint_time. States: pending/running/passed/failed/
externally_blocked/no_progress; no_progress is never passed. Completion requires
the certificate conjunction, not a worker's assertion. Atomic temporary-write
and rename; coordinator reads lane records, never multiple writers to one JSON.
Save exact resume instructions at every suspension. Do not invent a daemon.
