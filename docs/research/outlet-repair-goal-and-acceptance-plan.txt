REPAIR LOOP — REPEAT FOR EACH GATE

1. Reproduce the audited failure through the responsible production interface.
2. Add the smallest behavioral regression that fails because of the wrong result,
   not because of an import/build error. If another agent already fixed it, verify
   the fix and preserve it; do not manufacture a red state in the shared checkout.
3. State the invariant, cause, owner and intended change in the checkpoint.
4. Implement the fix at its owner; keep test expected results independent of the
   implementation formula. Do not mock the very behavior being asserted.
5. Rerun the failing test and directly affected integration checks.
6. Run the required targeted mutation check in an isolated temporary copy/worktree.
7. Save command receipts/evidence, update the gate, and proceed.

At most 3 repair attempts per hypothesis, 2 hypotheses per repeated blocker.
At the limit, write a concrete root-cause/blocker report and continue independent
work. Do not bypass the invariant, reduce assertions, change fixtures to easy data,
or repeatedly run an unchanged failing command. Leave blocked work explicitly open.
After two attempts without a new diagnostic fact, inspect the call path before
another edit. A completion-status edit is not progress on implementation.

G2: EVIDENCE DETECTION, CACHE AND SECURE DELIVERY

Perform high-resolution crop/tile refinement where whole-frame reduction loses
detail. Start with 20% tile overlap and 20% clipped context padding; record these
as sampling settings, not detector accuracy. Cover all image rotations, crop offsets,
resize factors and [ymin,xmin,ymax,xmax] conversion back to sensor coordinates.
Undo orientation exactly once. Test asymmetric corners and off-center crops.

Extend structured output and cache schemas together. Validate finite, ordered,
bounded boxes; nullable unresolved socket count; confidence provenance; observation
identity and unknown/ambiguous cases. Cache keys include input/crop, prompt/schema,
model/config and calibration versions. A cached response must preserve all metadata.
Never cache provider failure as zero detections. Bump cache versions appropriately.

Generate actual image crops derived from source pixels, with source/crop hashes,
capture/frame IDs, pixel box, orientation and detector metadata. Use existing
authenticated storage/routing and ownership checks. Do not expose raw filesystem
paths or arbitrary user-supplied URLs. Crop access checks ownership of its capture,
not merely knowledge of a crop ID. Handle unavailable/stale evidence explicitly.
Verify returned bytes decode and correspond to the recorded pixel region.

G3: CORRECT SUPPORT GEOMETRY AND UNCERTAINTY

Use canonical camera intrinsics/poses and world transforms. Compare camera-Z depth
with camera-Z depth, or ray distance with ray distance, never the two mixed.
Verify off-axis same-wall observations stay visible and foreground occluders do not.
Intersect measured mesh triangles for LiDAR-supported claims. A RoomPlan box plane
can support an explicitly inferred-plane estimate, not verified LiDAR support.
Absent/all-infinite depth, holes and grazing rays are uncertainty, not clear sight.

Use multiple rays over the photographed region. Preserve support surface identity,
input geometry/calibration revision, coordinate frame, observed region and evidence.
Define socket coordinates in one explicit frame. A faceplate center is not a
resolved socket target. Do not fabricate thickness or the standard duplex layout.
Allow a candidate with an uncertain location; do not force it onto the first wall.

G4: RECONCILIATION, IDENTITY AND OWNER DECISIONS

Merge only when support, bounded localization and actual reprojection into the
observed regions agree. Positive depth alone is insufficient. No universal merge
distance such as 20 cm. Numerical tolerances must come from documented image/pose/
support resolution and a reviewed validation set, not final acceptance outcomes.

Keep neighboring plates distinct; combine views of one plate without inventing
socket count; prevent transitive chains through ambiguous observations. A model
confidence score is not a calibrated probability. Consecutive duplicate frames do
not supply independent multiview confirmation.

Replay identical source data twice and reorder observations: IDs, evidence sets
and owner decisions must remain stable. Preserve all relevant caveats. Conflicting
owner edits need a conflict state, not silent last-write-wins. Persist correction
author/time and version using the existing authenticated revision/edit flow.

G5: CONSERVATIVE PERSONAL REACH CONTRACT

Do not reuse navigation eye height as shoulder/hand position. Define the actual
simple reach model and label it accurately. Require finite supplied bounds and an
explicit hand/shoulder reference when the model uses one. No implicit ADA defaults
of 0.38–1.22 m, no NaN/Infinity, negative distance, reversed bounds or unknown units.
Invalid input gets validation feedback and no affirmative reach result.

Keep separate outputs: identity/localization; route/approach; personalized geometric
reach; unknown power/availability/plug operation/ADA. Uncertainty must change the
result status, not merely append a warning beside a green pass.

Evaluate the observed socket region in the declared frame above verified local
finished floor. Missing floor means unknown height, not world zero or first floor.
Missing support/normal/operable target/profile prevents positive reach. A known
obstruction may still justify blocked while other attributes remain uncertain;
unknown is not an excuse to erase a real observed obstacle.

If supplied measurement uncertainty yields intervals, affirmative reach requires
the entire conservative distance/height interval inside the personal bounds and
the implemented reach corridor unobstructed. A threshold-crossing interval is
needs_verification. Do not invent zero uncertainty or substitute a 90% heuristic.
If numeric uncertainty cannot be justified, record unknown rather than fabricate
a confidence interval. Synthetic exact fixtures may declare zero uncertainty.

Passing a coarse geometric model is labeled within supplied modeled reach; it is
not proof of grasp, plug insertion, arm motion, strength or safe independent use.

G6: ROUTE AND REACH OBSTRUCTION ARE DISTINCT

Reuse/extend the appropriate navigation owner. Check a path from the actual chair
position, swept footprint, floor coverage and final stopping position. A clear
endpoint is insufficient. The approach preview must consume that evaluated path/
destination, not call unrelated object-center docking.

Suggested initial search settings: 0.10 m grid; 15 degree heading increments only
if orientation matters to the implemented footprint; 0.05 m refinement near narrow
passages/promising endpoints; bounded 50,000 search expansions. These are numerical
search limits, not physical accuracy claims. Exhaustion means search_inconclusive/
no_route_found_under_settings, not proof the real room is inaccessible.
Use continuous segment/capsule checks or sufficiently conservative geometric
intersections for collisions; coarse stepping must not jump a thin obstacle/gap.

Test a detour where a direct ray is blocked but a path exists. Unsupported floor
regions cannot be traversed as known-clear. Never substitute chair position (0,0)
when actual position is unknown. Maintain that unknown state in UI and exports.

Reach obstruction tests must consider obstacles between endpoints and relevant
heights. Do not require both endpoints to touch the same obstacle. Do not omit a
supporting cabinet merely because it is the outlet parent. A ray can establish an
obstruction but cannot alone establish full arm/hand passage; report model limits.
